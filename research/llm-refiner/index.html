LLM-Refiner: Putting Meaning Back in AMR

AMR parsers now match human annotators on the standard metric, yet they still get who did what to whom wrong. LLM-Refiner uses an LLM as a careful editor: it reads the parser's output, finds where the meaning went wrong, and makes small, checked repairs.

Ian Yuen, Douglas S. Chan, Nikita Mishra PDF

01 Why: high scores, wrong meaning

Abstract Meaning Representation (AMR) writes a sentence's meaning as a graph: the events, who took part, and how they relate. Graphs like these are a natural bridge between language models and symbolic reasoning. A human expert needs about ten minutes to annotate one sentence, though, so large AMR datasets depend on automatic parsers.

Strong parsers such as AMRBart now pass human inter-annotator agreement on SMATCH, the standard metric. SMATCH, however, rewards local overlap: it counts matching node–edge–node pieces. A graph can keep almost every piece and still say something different from the sentence.

The residual semantic gap: one misplaced edge can flip "the student leaves" into "the teacher leaves" while barely moving the score.

Why not let an LLM parse the sentence directly? LLMs on their own are still weaker AMR parsers. GPT-4o reaches about 0.60 SMATCH, against more than 0.83 for AMRBart. They are good at reasoning about meaning, but not at writing exact graph syntax. So we split the work between them.

02 What we built

  • LLM-Refiner, a post-editor. A strong parser does the parsing. An LLM then works through the meaning in three guarded steps (comprehend → diagnose → repair), and a validator makes sure the result is still a valid AMR graph. The LLM only edits; it never starts from scratch, which keeps hallucination in check.
  • A Semantic Test Protocol. We evaluate on GrAPES, a stress-test set of linguistically hard sentences, with SemBLEU, which compares multi-hop paths rather than single edges. This shows repairs that the standard AMR3 + SMATCH setup undercounts.

04 Case study: why one edge matters

Here is the same sentence side by side. AMRBart's graph matches the human gold graph everywhere except one edge, the one that says who leaves. LLM-Refiner removes that edge and adds the correct one.

Gold AMRhuman annotator

ask-01 ├─ ARG0: teacher ├─ ARG1: student └─ ARG2: leave-11 └─ ARG0: student

LLM-Refiner AMRAMRBart + repair

ask-01 ├─ ARG0: teacher ├─ ARG1: student └─ ARG2: leave-11 └─ ARG0: teacher✂ removed └─ ARG0: student+ added

Input sentence

The teacher asked the student to leave.

Regenerated from the AMR

The teacher asked the student for the teacher to leave.

A one-edge repair fixes meaning at three distances. SMATCH counts single hops, so it credits 1 improvement. SemBLEU counts multi-hop paths, so it credits all 3. Tap a row to trace it.

We call an element like this edge a semantic keystone: a small part of the graph that sits inside many meaning paths, so fixing it changes a lot of meaning for very little structural change. LLM-Refiner's repairs tend to land on keystones, which is why SemBLEU picks them up much better than SMATCH.

  • Linguistic context helps. Giving the LLM dependency parses and semantic roles from open-source tools improves the SemBLEU gain on GrAPES by 41% compared with going without.
  • It targets real failure modes. Repairs cluster in known parser weak spots: argument roles, coreference, negation, and missing details. LLM-Refiner repairs about 31% of GrAPES sentences and 6% of the everyday AMR3 sentences.
  • It works with more than one parser. Swapping AMRBart for SPRING still improves results (+2.1% SemBLEU on GrAPES), with smaller gains because SPRING starts from a stronger baseline.
  • Guardrails matter. Simply asking an LLM to "repair this AMR" was unstable. Removing the step-by-step reasoning, the linguistic context or the confidence filter made results worse.

06 Takeaway

AMR parsing and evaluation should ask not only whether a graph matches locally, but whether it preserves the sentence's meaning. Reliable automatic AMR could make symbolic datasets cheap to build at scale, which in turn helps unblock neuro-symbolic research.

Limitations: the Stage 2 prompt has to be tuned for each LLM, results inherit the domain coverage of the underlying parser, and specialized domains such as biomedical text remain future work.
